# d2o — адаптивный обход блокировок на C

**d2o** — самостоятельное развитие [d2k](https://github.com/necronicle/d2k) для маршрутизаторов **OpenWrt и Keenetic**. Сетевой движок обнаруживает проблемные соединения, проверяет варианты обхода и сохраняет работающие стратегии. В комплект входят веб-панель, поддержка Discord voice, DNS-помощник для Instagram/WhatsApp и локальный Telegram-прокси **на C11**.

**Идея:** подбирать решение по поведению реального трафика, а не поддерживать вручную список «заблокированных сайтов». Основной движок работает непосредственно на роутере, без обязательного VPN, WARP или внешнего сервера. Отдельные функции загрузки и DNS используют сетевую инфраструктуру проекта.

> **Независимый проект.** d2o не является официальным выпуском d2k или z2k и не представляет их команды. Названия некоторых исполняемых файлов и команд остаются `d2k` ради совместимости — это нормально и не означает установку из другого репозитория. Работоспособность конкретной стратегии зависит от сети, прошивки и сервиса.

## Возможности

| Направление | Что делает d2o |
|---|---|
| **TCP / TLS 1.2–1.3 / HTTP** | Обнаружение проблем и автоматическая проверка вариантов обхода |
| **UDP / QUIC (HTTP/3)** | Анализ и ограниченные пробы для QUIC-трафика |
| **Каталог стратегий** | Запоминание подтверждённых решений и повторное использование |
| **Discord voice** | Отдельная обработка голосового UDP/STUN-трафика |
| **Telegram** | Прозрачный локальный прокси `d2ktg` на C11, MTProto через WSS |
| **Instagram / WhatsApp** | Проверяемые DNS-записи с фоновым обновлением |
| **Веб-панель** | Статус, диагностика, обнаружение, управление и обновления |
| **Роутеры** | IPv4/IPv6, OpenWrt (nftables/iptables) и Keenetic (Entware) |
| **Релизы** | Собственный канал d2o с Ed25519-подписью и SHA-256 |

d2o **не является оболочкой над Zapret или nfqws**: datapath (`d2kd`) и контроллер (`d2kc`) — собственные компоненты на C. Совпадение имён `d2k` с исходным проектом связано с совместимостью установленной службы и протоколов.

### Как работает подбор

```text
Устройство в локальной сети
            │
            ▼
   Firewall → NFQUEUE
            │
            ▼
         d2kd
     обработка пакетов
            │
            ▼
         d2kc
  обнаружение и измерение
            │
      ┌─────┴──────┐
      ▼            ▼
 подтверждено   не подтверждено
      │            │
      ▼            └── не сохранять как успех
 сохранить план
      │
      ▼
 применять к подходящему трафику
```

Первое открытие нового сайта может быть медленнее: системе нужно провести измерения. Простой факт отправки пробы, успешный TCP connect или STUN-ответ **не гарантируют**, что приложение действительно заработало. Не весь трафик требует обхода, и не каждый блокируемый ресурс получится автоматически восстановить.

## Установка

Установщик d2o находится в [`scripts/install.sh`](scripts/install.sh). Он по умолчанию выбирает **собственный подписанный выпуск из `t0fox/d2o`**, определяет архитектуру, проверяет Ed25519-подпись метаданных и SHA-256 архива до применения комплекта. **Сборки из `necronicle/d2k` и `t0fox/r2o` не подставляются.** Если подходящий подписанный релиз ещё не опубликован, установка завершится с ошибкой, а не подменит его неподписанными файлами из ветки.

Нужны доступ `root` по SSH, NFQUEUE и совместимая архитектура. Для OpenWrt ориентируйтесь как минимум на **21 МиБ в разделе с `/opt`** и **18 МиБ свободного места в `/tmp`** под временную распаковку; проверка в установщике может потребовать больше в зависимости от платформы и уже установленной версии. На OpenWrt `/tmp` обычно находится в оперативной памяти. Для роутера с маленькой флеш-памятью предусмотрите USB/внешний overlay.

### OpenWrt

Подключитесь к роутеру:

```sh
ssh root@192.168.1.1
```

**Установка через `wget`** (выполнять в SSH на роутере):

```sh
wget -qO /tmp/d2o-install.sh https://raw.githubusercontent.com/t0fox/d2o/main/scripts/install.sh && sh /tmp/d2o-install.sh
```

**Или через `curl`:**

```sh
curl -fsSL https://raw.githubusercontent.com/t0fox/d2o/main/scripts/install.sh -o /tmp/d2o-install.sh && sh /tmp/d2o-install.sh
```

После установки можно удалить временный установщик:

```sh
rm -f /tmp/d2o-install.sh
```

Для OpenWrt 22.03+ с `fw4/nftables` установщик использует штатные `opkg` (24.10 и старее) или `apk` (25.12 и новее) и пытается поставить недостающие модули/утилиты. **Entware на OpenWrt не нужен.** При отсутствии HTTPS-загрузчика, актуальных сертификатов или доступа к репозиториям пакетов сначала исправьте эти проблемы — установщик покажет, какой именно пакет не удалось получить. Проверить пространство:

```sh
df -h /opt /tmp
```

Не запускайте параллельно d2o, z2k или Zapret для обработки одного и того же трафика: их правила могут конфликтовать.

### Keenetic

Перед установкой один раз настройте **Entware на USB-накопителе** согласно [официальной инструкции Keenetic](https://help.keenetic.com/hc/ru/articles/360021214160). В компонентах KeeneticOS нужны «Модули ядра подсистемы Netfilter» и «Поддержка открытых пакетов» (OPKG); наличие IPv6 зависит от версии прошивки.

Входить нужно **в Entware**, обычно по порту `222`, а не в CLI KeeneticOS:

```sh
ssh root@192.168.1.1 -p 222
```

Установите зависимости Entware (один раз):

```sh
opkg update
opkg install curl ca-bundle iptables ipset kmod_ndms xtables-addons_legacy openssl-util
```

Затем **в том же SSH-сеансе Entware** выполните ту же короткую команду:

```sh
curl -fsSL https://raw.githubusercontent.com/t0fox/d2o/main/scripts/install.sh -o /tmp/d2o-install.sh && sh /tmp/d2o-install.sh
```

Если до этого работал z2k, остановите его и отключите его автозапуск до запуска d2o. Порт `22`/telnet самого KeeneticOS **не подходит** для выполнения установщика.

### Если GitHub не открывается на роутере

Для первой загрузки установщика можно использовать HTTPS через резервный HTTP CONNECT-проводник проекта:

```sh
curl -fsSL --proxy http://213.176.74.63:9444 https://raw.githubusercontent.com/t0fox/d2o/main/scripts/install.sh -o /tmp/d2o-install.sh && sh /tmp/d2o-install.sh
```

Далее установщик сам сначала пробует загрузку через этот адрес, затем напрямую. Если оба варианта не сработали, проверьте DNS (`nslookup github.com`), доступ в интернет, корректность системного времени (`date`) и доверенные сертификаты. Проводник не заменяет подписанные релизы: перед установкой проверяются Ed25519 и SHA-256.

Если роутер совсем не может получить доступ к GitHub, используйте [релизы d2o](https://github.com/t0fox/d2o/releases) и ручную доставку **собственного** архива подходящей архитектуры. Ручная установка из распакованного каталога `D2K_LOCAL` не проверяет подпись автоматически — не используйте сторонние или непроверенные архивы. Подробнее о выпуске: [RELEASING.md](RELEASING.md).

### Архитектуры и архивы

| Архив подписанного выпуска | Архитектура |
|---|---|
| `d2k-arm64.tar.gz` | ARM64 / AArch64 |
| `d2k-arm.tar.gz` | ARMv7 EABI с VFPv3 |
| `d2k-mipsel.tar.gz` | MIPS32 little-endian |
| `d2k-mips.tar.gz` | MIPS32 big-endian |
| `d2k-mips64el.tar.gz` | MIPS64 little-endian N64 с FPU |
| `d2k-amd64.tar.gz` | x86-64 |
| `d2k-x86.tar.gz` | x86 / i686 |
| `d2k-riscv64.tar.gz` | RISC-V64 |
| `d2k-ppc64.tar.gz` | PowerPC 64 big-endian |

Несмотря на имена `d2k-*.tar.gz`, выпуск берётся из репозитория **d2o**. ARMv5/ARMv6, Lexra и MIPS64EL без FPU не поддерживаются. Только `uname -m` недостаточно для определения порядка байт MIPS — установщик проверяет userspace ABI.

## После установки

Проверьте сервис:

```sh
/opt/etc/init.d/S99d2k status
```

Убедитесь, что datapath и контроллер работают; затем откройте панель. Установщик печатает её адрес по завершении.

**Если сеть работает плохо**, остановите движок и снимите принадлежащие d2o правила:

```sh
/opt/etc/init.d/S99d2k stop
```

Режим по умолчанию — `MODE=apply`. Для наблюдения без активного подбора можно настроить `MODE=observe` в `/opt/d2k/config`, затем перезапустить службу.

## Веб-панель

По умолчанию интерфейс доступен в локальной сети по адресу **http://192.168.1.1:8090/** (если адрес роутера другой, замените его). Панель показывает состояние движка, обнаружение, каталог стратегий, Telegram, журналы и управление обновлениями.

**У панели нет аутентификации.** Не пробрасывайте TCP/8090 в интернет и не открывайте его с WAN.

## Управление

Команды намеренно сохранили имя `S99d2k` — при установке d2o это его штатная служба.

| Команда | Действие |
|---|---|
| `/opt/etc/init.d/S99d2k status` | Состояние компонентов |
| `/opt/etc/init.d/S99d2k start` / `stop` / `restart` | Запустить, остановить или перезапустить |
| `/opt/etc/init.d/S99d2k engine-restart` | Перезапустить datapath и контроллер |
| `/opt/etc/init.d/S99d2k reapply` | Повторно применить правила |
| `/opt/etc/init.d/S99d2k heal` | Восстановить свои правила и Telegram |
| `/opt/etc/init.d/S99d2k clear-found` | Удалить найденные стратегии |
| `/opt/etc/init.d/S99d2k telegram-enable` / `telegram-disable` | Включить или отключить Telegram |
| `/opt/etc/init.d/S99d2k telegram-restart` | Перезапустить локальный Telegram |
| `/opt/etc/init.d/S99d2k update-check` | Проверить подписанный релиз |
| `/opt/etc/init.d/S99d2k update-install` | Запустить установку обновления |
| `/opt/etc/init.d/S99d2k update-auto-on` / `update-auto-off` | Ночные автообновления |

**Конфигурация:** `/opt/d2k/config`. **Состояние и каталог:** `/opt/d2k/state/`. **Журналы:** `/opt/d2k/log/`.

```sh
tail -n 100 /opt/d2k/log/d2kd.log
tail -n 100 /opt/d2k/log/telegram.log
tail -n 100 /opt/d2k/log/update.log
```

Очистка `clear-found` необратимо удаляет каталог подобранного: затем d2o будет искать стратегии заново.

## Telegram

В d2o работает **`d2ktg` на C11**, а не Rust-прокси r2o. Он прозрачно принимает подходящие соединения Telegram через локальные правила и выбирает маршрут для Telegram DC1–DC5. Ручная настройка MTProxy в приложении обычно не требуется.

1. Правила перенаправляют подходящий TCP-трафик на локальный listener; исходный адрес помогает определить DC.
2. Прокси сверяет адрес и MTProto-рукопожатие, затем проверяет WSS-маршруты Telegram и предусмотренные Cloudflare Worker/CF-резервы.
3. Подтверждённые маршруты могут повторно использоваться; для отказов учитываются причина, задержка и cooldown.
4. Прокси передаёт MTProto в обе стороны. Успешный HTTP 101 или доступный TCP-порт сам по себе не считается успешным MTProto-обменом.

Прямой TCP не является автоматическим маршрутом; `TG_DIAGNOSTIC_DIRECT_TCP=1` предусмотрен только для диагностики. Для резерва могут понадобиться доступные Cloudflare-адреса. **Состояние локального listener не доказывает, что Telegram или медиа работают в текущей сети.**

Диагностика DC, MTProto и WSS:

```sh
/opt/sbin/d2ktg --check-telegram-dc-matrix
/opt/sbin/d2ktg --discover-telegram-dc-matrix
/opt/sbin/d2ktg --check-telegram-wss-matrix
```

Результаты включают фазу отказа и могут зависеть от состояния сети. Описание портирования, проверок и известных ограничений — [матрица Telegram C11](docs/telegram-c11-port-matrix.md).

## Discord voice

Для Discord используется отдельный UDP/STUN-путь с обнаружением проблем и подбором временных планов. **Успешный STUN не равен передаче слышимого голоса:** работу двунаправленного аудио, повторные подключения и длительные голосовые сеансы нужно проверять в реальном Discord. Не считайте найденную стратегию гарантией качества звонка.

## Instagram и WhatsApp

DNS-помощник поддерживает проверяемые записи для Instagram/WhatsApp Web: запрашивает адреса у резолвера проекта, сверяет их принадлежность Meta и доступность, затем периодически обновляет собственные записи. Это **отдельная вспомогательная функция**, а не принцип работы основного движка.

```sh
/opt/d2k/d2k-instagram-dns.sh refresh
cat /opt/d2k/state/instagram-ip-hosts.tsv
tail -n 30 /opt/d2k/log/instagram-dns.log
```

Сервис обновляет записи в фоновом режиме и при ошибках может сохранять прежние. Не выключайте проверку сертификатов ради обхода сбоев.

## Обновления

d2o использует **собственный** канал `t0fox/d2o`, отдельный от d2k и r2o. В опубликованном выпуске метаданные `latest.json` подписываются Ed25519, а архивы сверяются с подписанными SHA-256. Приватный ключ подписи не должен храниться в репозитории; подготовка выпусков описана в [RELEASING.md](RELEASING.md).

```text
CI и сборки архитектур
          ↓
подписанные latest.json + SHA-256
          ↓
проверка перед установкой
          ↓
замена комплекта + health-check
          │
    успех / откат при сбое
```

При включённом `AUTOUPDATE=1` обновлятор проверяет выпуски ночью, в интервале **03:00–05:00**. Установка нового выпуска предусматривает резервную копию и возврат при ошибке проверки служб. Можно отключить автоустановку в панели или командой `update-auto-off`; ручная установка через `update-install` остаётся доступна.

**Важно:** наличие workflow релиза в исходниках не равно наличию опубликованного подписанного релиза. Если [страница выпусков d2o](https://github.com/t0fox/d2o/releases) не содержит совместимого подписанного комплекта, обычный установщик ничего не установит. Для разработки есть отдельный неподписанный режим `D2K_SOURCE=ref`, **не предназначенный для обычной установки на роутер**.

## Удаление

**Полное удаление** удаляет собственные службы, правила, конфигурацию и найденные стратегии d2o. Запускайте под `root` на роутере:

```sh
wget -qO /tmp/d2o-uninstall.sh https://raw.githubusercontent.com/t0fox/d2o/main/scripts/uninstall.sh && sh /tmp/d2o-uninstall.sh
```

Или через `curl`:

```sh
curl -fsSL https://raw.githubusercontent.com/t0fox/d2o/main/scripts/uninstall.sh -o /tmp/d2o-uninstall.sh && sh /tmp/d2o-uninstall.sh
```

**Сохранить конфигурацию и каталог** при удалении:

```sh
D2K_KEEP_STATE=1 sh /tmp/d2o-uninstall.sh
```

Эту строку запускайте **вместо** обычного `sh /tmp/d2o-uninstall.sh`, не после него: по умолчанию состояние уже будет удалено. При необходимости удалите временный скрипт `rm -f /tmp/d2o-uninstall.sh`. Деинсталлятор оставляет системные пакеты `opkg`/`apk` и не должен удалять чужие правила firewall.

## Настройки и совместимость

### Политика доступа Keenetic

Можно ограничить обработку устройствами выбранной политики Keenetic. Создайте политику с обычным провайдерским выходом, назначьте устройства и добавьте в `/opt/d2k/config`:

```sh
KEENETIC_POLICY="Имя политики"
```

Затем `/opt/etc/init.d/S99d2k restart`. Если имя не найдено, обработка устройств не включается; удаление этой настройки возвращает работу для всей сети. Telegram и DNS-помощник имеют отдельные правила и не обязаны следовать ограничениям политики.

### Windows и TCP timestamps

Если на других устройствах сайт открывается, а на Windows есть зависания, для **диагностики отдельных TCP-стратегий** можно попробовать в терминале администратора:

```bat
netsh interface tcp set global timestamps=enabled
```

Отменить изменение:

```bat
netsh interface tcp set global timestamps=disabled
```

Это не универсальное решение и не устраняет блокировки по IP. Включать timestamps всем пользователям заранее не требуется.

## Архитектура

```text
LAN → firewall / NFQUEUE
         │
         ├── d2kd       обработка пакетов и исполнение стратегий (C)
         ├── d2kc       обнаружение, пробы, каталог (C)
         ├── d2kfetch   сетевые проверки (C)
         ├── d2kpanel   HTTP backend и веб-панель
         └── d2ktg      локальный MTProto/WSS-прокси (C11)

S99d2k              запуск, остановка и восстановление правил
d2k-update.sh        подписанные обновления и rollback
scripts/install.sh   маршрутизация установки по архитектуре и ABI
```

Главная конфигурация и сохранённые решения находятся отдельно от исполняемых файлов. Для OpenWrt имеется собственный хук автозапуска через `procd`, для Keenetic используется среда Entware.

## Разработка

```sh
sh scripts/check.sh
make -C telegram test
make -C panel test
make -C relay-enroll test
```

Сборка по архитектурам выполняется через `scripts/build-router.sh`, с Zig и инструментами из [RELEASING.md](RELEASING.md). CI проверяет C, Telegram C11, интеграцию, QEMU и релизные сценарии; успешные тесты не заменяют испытаний на физических роутерах.

Указанная в исходном репозитории лицензия: **MIT**. Используйте проект с соблюдением применимых правил и учитывайте, что результат зависит от конкретной сети и прошивки.
