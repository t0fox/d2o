# Поле 12.10.2026: эталон объёма через VPS — обрыв на 16 КБ подтверждён числом

Сборка `main 6564bfa` на роутере (`/opt/d2k/field-1012q-6564bfa`, пустой каталог).
Владелец: «еле качается, остался блок по объёму» и «проверь нужный объём через
VPS, там правильно отдаст». Эталон снят с VPS 192.0.2.44 (ключ владельца
`~/.ssh/z2k_vps_ed25519`), сравнение — тем же URL с роутера через провайдера.

## Эталон против провайдера

| Ресурс | С VPS | С роутера через провайдера |
|---|---|---|
| `style.sndcdn.com/css/soehne-*.css` | **301 328** | **15 985 / 15 984 / 15 986**, затем зависание на все 30 с таймаута, трижды подряд |
| `a-v2.sndcdn.com/assets/css/app-*.css` | 123 726 | 123 726, 0,33 с |
| `a-v2.sndcdn.com/assets/1-*.js` | 315 405 | 315 405, 0,29 с |
| `a-v2.sndcdn.com/assets/57-*.js` | 52 980 | 52 980, 0,22 с |

Это первое прямое числовое доказательство объёмного обрыва: истинный размер
301 КБ, доходит **15 985 байт тела ≈ 16 КиБ**, воспроизводимо до байта в трёх
попытках, дальше тишина до таймаута. Оценка владельца «16 кб» точна.

Второй вывод не менее важен: `a-v2.sndcdn.com` отдаёт свои 123 КБ и 315 КБ
целиком и быстро. Блокируется **не весь CDN SoundCloud, а конкретное имя**
`style.sndcdn.com`. Прежняя запись `2026-10-12a` называла виновником объём на
нескольких именах; по этим числам из них режется одно.

Сопутствующий эталон: корень `style.sndcdn.com` отдаёт 403 с телом 243 байта
и **с VPS тоже**. Короткий ответ зонда — честное поведение сервера на этом
пути, а не блокировка. Это ровно та посылка, на которой построена правка
`6564bfa`.

## Поправка к pcap-выводам предыдущей записи

Разбор захватов показал, что часть «застывших» потоков читалась неверно:
соединения без входящих байтов в `sc4` начинались до окна захвата (первый
пойманный пакет — голый ACK без SYN) и были закрыты клиентом через ~19,6 с,
то есть это обычные keep-alive сокеты, а не свежие замороженные потоки.
Живые потоки к `style.sndcdn.com` принимали 20 467–24 751 байт **провода**
(не тела) за 18–21 входящий пакет. Телесное число 15 985 из прямого опыта
точнее любого из них.

## Почему D2K этого ещё не снял

- План `plan-ad82d529` найден **запасным перебором**, не замером:
  `00:38:56 ПОДТВЕРЖДЕНО собственным зондом: plan-ad82d529 (путь: перебор)`.
- Он принят как **частичный обход**: `рукопожатие снято, поток режется после
  ~30 пакетов (нужно 50, бюджет 25 — поле 04.10, коробка не измерена);
  привязка помечена «оборван»`. Строки `бюджет потока пройден` по этой цели
  в журнале нет ни одной.
- К **живым потокам он не применяется**: в захватах после установки
  приветствия живых потоков чистые (`1428 + 111`, обычный разрез по MSS,
  ttl=63), без подписи приманки или разреза, которая есть у каждого зонда
  (ttl=64). Трассы исполнения для TLS/443 в датапате нет вообще:
  `datapath/http_trace.c:40` печатает её только для порта 80.
- Входящий объёмный обрыв по этой цели **так и не измерен**. Новая ветка
  правки сказала правду: `бюджет объёма не проверен: ответ зонда завершён на
  243 байт, меньше измеряемой полосы 12 КБ`. Зонд добирал объём шестью
  мелкими ответами 403 по 243–263 байта и в полосу не входил ни разу, тогда
  как живой клиент тянет один объект на 301 КБ.

Отсюда следующий измеримый шаг, уже без догадок: зонду нужен **настоящий
ресурс этой цели достаточного объёма**. Подсказки ресурсов сейчас берутся
только из ссылок на стили в собственном identity-ответе
(`core/include/d2k_resource.h`, только `.css`, по одному на хост), а путь
`/css/soehne-*.css` лежит за CSS-файлом с другого хоста и в подсказки не
попадает. Пока зонд просит `/`, полоса не проверяется, и класс не измерить.

## QUIC: класс Б по журналу и по исследованиям

Разбор журнала класса Б (rutracker, fost, nnmclub, kinozal, lostfilm):
- Неизменённый Initial — `0/3`, ответа нет.
- **С одиннадцатью приманками Initial проходит: `3/3`.** Дальше срыв на
  следующей стадии: у rutracker и lostfilm `ответ есть, рукопожатия нет`,
  у kinozal, nnmclub и fost `рукопожатие есть, поток встал без полного
  ответа ниже порога`.
- `фрагменты доходят вообще (контрольное имя)` даёт `0/3` и у класса А
  (enimerosi), поэтому итоговое «фрагм. не доживают» — свойство канала,
  а не признак класса. Мои прежние выводы опирались на эту строку зря.
- Класс А отличается тем, что у него неизменённый Initial проходит сразу
  (`3/3`), и приём находится на лестнице TTL.

Исследования (FOCI 2026, замеры в РФ март–апрель 2026): ТСПУ расшифровывает
QUIC Initial, читает SNI во вложенном ClientHello и дропает пакет in-path,
затем держит остаточную цензуру 420 с по четвёрке адрес-порт, причём любой
следующий пакет сбрасывает таймер; цензура односторонняя. Цензурируется
**только версия 1**, версия 2 не цензурируется ни в одной из трёх точек
замера. Для части доменов блокировка не срабатывает, если по той же четвёрке
сначала прошли нейтральные UDP-данные. Это готовый набор различающих
вопросов, проверяемых парным опытом. Ссылки — в отчёте агента, основная:
`https://www.petsymposium.org/foci/2026/foci-2026-0010.pdf`.

## Границы

- Опыты с роутера сделаны его собственным curl: это измерение **линии**, а не
  работы плана. Трафик роутера идёт не через ту же цепочку, что трафик LAN,
  и в датапате этих потоков нет.
- Живой критерий по-прежнему unknown: бюджет потока измеряется только зондом.
- Сборка оставлена на роутере, автообновление выключено. Возврат прода:
  `sh /opt/d2k/field-1012q-6564bfa/rollback.sh`.
