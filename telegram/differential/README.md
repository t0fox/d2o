# Дифференциальная проверка MTProto framing

Запусти из корня `d2o`:

```sh
python3 telegram/differential/run.py
```

Нужны Python 3.11+, `git`, C11-компилятор, OpenSSL headers/libraries, `cargo` и
`rustup`. Скрипт загружает `t0fox/z2kOW`, проверяет точный донорский commit
`4ef79fb99c30c233488623c04ec13c8097a614e0`, извлекает только
`platform/openwrt/tg-proxy` во временный каталог и добавляет туда временный
Rust runner. Исходники донора не изменяются. Для локального клона можно передать
`--donor-repo /путь/к/z2kOW`.

Оба runner получают один детерминированный corpus. Результаты сравниваются
побайтно. 144 сценария проверяют Abridged, Intermediate и Padded Intermediate,
несколько пакетов в потоке, произвольное разбиение входа на чтения, потоковый
AES-256-CTR, raw mode, неполный пакет на EOF и отклонение пакета больше 4 МиБ.
Seed генератора закреплён в `run.py`.

Дополнительно Rust создаёт 30 secret Obfuscated2 handshakes для normal/media
DC1–DC5 и трёх transport tags; C сверяет поля через `tg_mtproto_parse_secret`
и отклонение неверного secret. Ещё 30 Rust direct init проверяются через
`tg_mtproto_parse_obfuscated2`. Генерируемые handshake содержат случайные
байты; сравниваются проверяемые протоколом инварианты, а не сами случайные
пакеты. Всего C/Rust прогоняет 90 сравнений handshake.

Для карты DC runner дополнительно сверяет 116 сценариев: все 33 встроенных
IPv4 адреса по normal/media DC подсказкам, неизвестные адреса и синтетические
официальные `dcOption` для TCP-only порта, запрета CDN-маршрута, IPv6,
неоднозначности и выбора между портами. В Rust используются функции `dc_map`,
в C — `tg_dc_resolve`; сценарии поступают обоим процессам в одном TSV-потоке и
сравниваются побайтно. C содержит пять дополнительных встроенных IPv6 fallback
адресов, которых нет в Rust `DEFAULT_DC_ROUTES`; общий путь поиска IPv6 в
официальной карте проверяется дифференциально.

Для проверки WebSocket используется Rust `tungstenite 0.24` и C
`tg_ws_reassembly_feed` из production `tg_ws_pump`. 44
детерминированных сценария проверяют сборку фрагментированных binary/text
сообщений, ping/pong между фрагментами, частичные чтения, границы
125/126/65535/65536 байт, неверные последовательности кадров, UTF-8 и
превышение лимита 4 МиБ. TLS-тест на loopback-соединении отдельно проверяет сборку
фрагментированного binary-сообщения с ping между кадрами и отказ pump от text-сообщения.

Сверка покрывает handshake, MTProto framing/CTR, WebSocket messages и правила
карты DC. Она не подтверждает полную эквивалентность моста, TLS handshake,
противодавления runtime, выбора и переключения сетевого маршрута или жизненного
цикла соединений.
