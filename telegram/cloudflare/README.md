# Cloudflare Worker для Telegram

Если сообщения, фото и видео уже работают через стандартный Worker Flowseal,
его можно оставить. Для соединений, которым требуется исходящий TCP 5222,
добавьте отдельный Worker D2O и настройте список разрешённых IP.

| Worker | Обычный Telegram и медиа | Соединения с обязательным TCP 5222 |
| --- | --- | --- |
| [Стандартный Flowseal](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/EN/CfWorker.md) | `/apiws`, исходящий TCP 443 | Требуется Worker D2O |
| [Расширенный D2O](worker.js) | Совместимый `/apiws`, исходящий TCP 443 | `/d2o/apiws/5222`, TCP 5222 к точному IP из списка |

Оба порта в таблице относятся к соединению **от Worker до Telegram**. Адрес
`workers.dev` в панели D2O указывается без порта. Для 5222 Worker D2O
подтверждает открытие TCP-сокета перед переключением на WebSocket. Успешное
открытие сокета и ответ самого Telegram проверяются отдельно.

## Настройка из панели D2O без SSH

1. Откройте **Telegram → Мои Workers**. В блоке **Настройка Cloudflare
   Worker** нажмите **Скопировать код Worker**. Кнопка **Скачать .js**
   сохранит тот же исходник из установленной версии панели.
2. [Создайте Worker в Cloudflare](#1-создайте-worker-в-cloudflare),
   вставьте код в **Edit code** и нажмите **Deploy**.
3. Если вам нужен TCP 5222, нажмите **Скопировать IP для TCP 5222**.
   Панель показывает дату получения подтверждённой карты, её состояние
   и число уникальных адресов. Вставьте строку в
   [переменную D2O_TG_5222_TARGETS](#4-добавьте-список-в-cloudflare).
4. [Добавьте hostname Worker](#5-подключите-worker-в-панели-d2o) в этом
   же окне панели, нажмите **Сохранить** и
   [проверьте Telegram](#6-проверьте-telegram-и-маршрут).

Если браузер запретил автоматическое копирование, в окне появится
выделенный текст. Нажмите **Ctrl+C** в Windows или Linux, **⌘+C** на macOS.
Это работает и при открытии панели по HTTP на локальном IP.

При недоступной карте дождитесь её обновления и откройте окно заново.
При пустом списке оставьте 5222 выключенным. На старых версиях панели
код можно взять из [worker.js](worker.js), а IP получить через SSH по
инструкции ниже.

## 1. Создайте Worker в Cloudflare

Этот шаг выполняется **в браузере на компьютере**. Понадобятся аккаунт
Cloudflare и установленный D2O с доступом к его панели.

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) и в нужном
   аккаунте откройте **Workers & Pages**.
2. Нажмите **Create application**, выберите **Create Worker**. Если Cloudflare
   предлагает **Start with Hello World**, выберите этот шаблон. Задайте имя,
   например `telegram-d2o`, и нажмите **Deploy**, чтобы создать Worker.
3. Откройте созданный Worker, нажмите **Edit code**. Возьмите код из панели
   D2O или откройте [worker.js](worker.js) на GitHub, нажмите **Raw** и
   скопируйте весь файл. Замените код шаблона и снова нажмите **Deploy**.
4. На странице Worker найдите его рабочий адрес `workers.dev`. Если адрес
   выключен, включите его на вкладке **Domains**. При первом использовании
   Cloudflare может предложить выбрать поддомен аккаунта. Используйте адрес
   развёрнутого Worker, показанный Cloudflare. Он выглядит как
   `https://telegram-d2o.ИМЯ-АККАУНТА.workers.dev`.

Для работы только на 443 переходите сразу к [подключению в D2O](#5-подключите-worker-в-панели-d2o).
Тот же скрипт и инструкция входят в архив `d2k-telegram-worker.tar.gz` в релизах D2O.
[Инструкция Cloudflare по созданию Worker](https://developers.cloudflare.com/learning-paths/workers/get-started/first-worker/).

## 2. Войдите на роутер по SSH для ручной настройки

SSH открывает командную строку роутера на компьютере. Подключите компьютер
к домашней сети роутера по Wi-Fi или кабелю. Возьмите локальный IP роутера
из адресной строки его веб-панели или из поля «Основной шлюз» в настройках
сети компьютера. Используйте учётную запись SSH и порт, настроенные на роутере.

| Компьютер | Где вводить команду `ssh` |
| --- | --- |
| Windows | Откройте через «Пуск» **PowerShell** или **Командную строку (CMD)**. |
| Linux | Откройте приложение **Терминал**. |
| macOS | Нажмите **⌘ + Пробел**, найдите **Terminal** и откройте его. |

В примерах `192.168.1.1` — локальный адрес роутера. Подставьте свой адрес,
если он отличается. Для OpenWrt обычно используется `root` и порт 22.

```sh
ssh root@192.168.1.1
```

На Keenetic нужна командная строка **Entware/BusyBox**, из которой виден
каталог `/opt`. Если Entware SSH работает на порту 222, команда выглядит так.

```sh
ssh -p 222 root@192.168.1.1
```

Если для Entware настроен порт 22 или другой порт, укажите его после `-p`.
При первом входе сверьте отпечаток ключа SSH роутера и подтвердите подключение
к своему устройству. Введите пароль SSH, если он запрошен. При наборе символы
пароля обычно не отображаются. После входа приглашение может выглядеть как
`root@OpenWrt:~#` или `~ #`. Символы приглашения копировать не нужно.

**Все команды с `/opt/...` ниже вводите в том же окне после входа по SSH.**
Если окно по-прежнему показывает `PS C:\...` или `C:\...`, вы ещё в командной
строке Windows. Выйти с роутера можно командой `exit`.

[SSH в Windows](https://learn.microsoft.com/en-us/windows/terminal/tutorials/ssh) ·
[SSH в OpenWrt](https://openwrt.org/docs/guide-quick-start/sshadministration) ·
[Вход в Entware на Keenetic](https://support.keenetic.com/hero/kn-1013/en/20980-installing-the-entware-repository-on-a-usb-drive.html).

## 3. Получите IP для TCP 5222

`/opt/d2k/state/telegram-dc-map.json` — сохранённая карта адресов
дата-центров Telegram (DC), полученная D2O из подтверждённого ответа
`help.getConfig`. При неудачном обновлении D2O сохраняет последнюю
подтверждённую карту. Посмотреть файл на роутере можно следующими командами.

```sh
ls -l /opt/d2k/state/telegram-dc-map.json
cat /opt/d2k/state/telegram-dc-map.json
```

`ls` показывает, существует ли файл, а `cat` выводит содержимое. Карта
может отображаться одной длинной строкой. В массиве `endpoints` каждая
запись описывает отдельную точку подключения.

| Поле | Что означает |
| --- | --- |
| `id` | Номер дата-центра Telegram. У одного DC может быть несколько записей. |
| `address` | Точный IPv4 или IPv6 точки подключения. |
| `port` | TCP-порт этой записи, например `443` или `5222`. |
| `this_port_only` | При `true` исходный порт обязателен. При `false` у записи нет этого ограничения. |
| `media_only` | При `true` запись предназначена для медиа. |

Список разрешений для 5222 формируйте **только из записей с числовым
`"port": 5222`**, независимо от `this_port_only`. Один IP может встречаться
несколько раз. Если тот же IP есть и на 443, и на 5222, его достаточно внести
один раз. Копирование всех IP карты расширило бы доступ Worker на 5222 и
для адресов, объявленных Telegram только для других портов. Полный JSON
может содержать поля `secret`, поэтому для настройки копируйте только вывод
команды ниже.

Вставьте **всю команду одним блоком** в SSH-окно роутера и нажмите Enter
после последней строки. Она использует `awk` из BusyBox и работает с
форматом карты D2O, в котором записи `endpoints` являются плоскими объектами.

```sh
awk '
  BEGIN { RS = "}" }
  !in_endpoints {
    if (!match($0, /"endpoints"[[:space:]]*:[[:space:]]*\[/)) next
    $0 = substr($0, RSTART + RLENGTH)
    in_endpoints = 1
  }
  /^[[:space:]]*\]/ { exit }
  /"port"[[:space:]]*:[[:space:]]*5222[[:space:]]*(,|$)/ {
    if (match($0, /"address"[[:space:]]*:[[:space:]]*"[0-9A-Fa-f:.]+"/)) {
      ip = substr($0, RSTART, RLENGTH)
      sub(/^[^:]*:[[:space:]]*"/, "", ip)
      sub(/"$/, "", ip)
      if (!seen[ip]++) printf "%s%s", (count++ ? "," : ""), ip
    }
  }
  END { if (count) printf "\n" }
' /opt/d2k/state/telegram-dc-map.json
```

При наличии подходящих записей появится одна строка вида
`IP_ИЗ_КАРТЫ_1,IP_ИЗ_КАРТЫ_2`. В реальном выводе будут ваши IP.
Скопируйте только эту строку. При отсутствии записей команда вернёт вас
к приглашению без вывода.

## 4. Добавьте список в Cloudflare

1. В браузере откройте **Workers & Pages → ваш Worker D2O → Settings**.
2. В **Variables and Secrets** нажмите **Add**. Если переменная уже есть,
   откройте её для редактирования.
3. В поле **Type** выберите **Text**. В **Variable name** введите
   `D2O_TG_5222_TARGETS` с тем же регистром.
4. В **Value** вставьте строку из панели D2O или SSH. В этом поле должны быть только точные
   IP через запятую. IPv6 вставляйте без квадратных скобок. Уберите кавычки,
   префиксы CIDR, номера портов, домены и `https://`.
5. Сохраните запись и нажмите **Deploy**, если интерфейс предлагает
   применить изменения отдельным шагом. Дождитесь завершения развёртывания
   и проверьте, что переменная отображается в настройках этого Worker.

| Поле Cloudflare | Что ввести |
| --- | --- |
| **Type** | `Text` |
| **Variable name** | `D2O_TG_5222_TARGETS` |
| **Value** | Строка из панели или команды SSH. Формат при двух адресах — `IP_ИЗ_КАРТЫ_1,IP_ИЗ_КАРТЫ_2`. |

При пустом списке 5222 отключён. Для 443 Worker D2O уже знает допустимые
подсети Telegram. Если для подтверждённой точки на 443 вне этих подсетей
требуется явный допуск, добавьте её точный IP в отдельную текстовую
переменную `D2O_TG_443_TARGETS`. [Настройки переменных в Cloudflare](https://developers.cloudflare.com/workers/configuration/environment-variables/#add-environment-variables-via-the-dashboard).

## 5. Подключите Worker в панели D2O

1. Скопируйте из Cloudflare только имя хоста, например в форме
   `telegram-d2o.ИМЯ-АККАУНТА.workers.dev`. Оставьте за пределами поля
   `https://`, номер порта, конечный слеш и путь `/apiws`.
2. Откройте веб-панель D2O и перейдите в **Telegram → Мои Workers**.
3. Вставьте hostname в **Домен Worker**, нажмите **Добавить домен**,
   затем **Сохранить**. В списке может быть до восьми доменов. При сохранении
   C11 перезапустится, и текущие соединения Telegram могут переподключиться.
4. Если туннель выключен, нажмите **Включить туннель**. В обычном режиме
   оставьте выключенным переключатель **Только выбранный маршрут**. В этом
   режиме доступны и Cloudflare Proxy, и Worker.

Работающие домены Flowseal можно оставить в списке. Если окно **Мои Workers**
доступно только для просмотра, для сохранения домена нужно включённое
управление в конфигурации панели.

## 6. Проверьте Telegram и маршрут

1. Подключите телефон или компьютер к сети этого роутера. На телефоне
   временно выключите мобильные данные, чтобы проверка шла через роутер.
2. Переподключите Telegram. Отправьте сообщение, загрузите фото и запустите
   видео, которого ещё нет в кэше. Проверьте, что видео продолжает
   загружаться после начала воспроизведения.
3. Пока идёт передача, откройте **Telegram** в панели D2O. Посмотрите
   **Маршруты** и активность DC. Для проверяемой сессии ищите
   **Прокси Cloudflare** или **Cloudflare Worker**, номер DC и
   **Ответ Telegram подтверждён**. Статус «Маршрут выбран» означает, что
   ответ Telegram ещё ожидается.
4. Для отдельной проверки Worker временно включите **Только выбранный
   маршрут** и выберите **Cloudflare Worker**. Дождитесь перезапуска C11
   и повторите проверку. При нескольких настроенных доменах такой выбор
   проверяет маршрут Worker в целом. После проверки выключите переключатель,
   чтобы снова были доступны оба маршрута.
5. Для подтверждения именно 5222 воспроизведите соединение Telegram,
   использующее исходный TCP 5222, и проверьте ответ Telegram через Worker.
   Успешная загрузка медиа сама по себе может пройти на 443. При отказе
   на 5222 панель может показать **Worker не подтвердил TCP 5222**.

Если на роутере уже есть `tcpdump`, можно посмотреть исходные подключения
на 5222. Запустите команду в SSH, переподключите Telegram и сверяйте адрес
назначения с картой DC. Для остановки нажмите **Ctrl+C**. Если подходящего
подключения не видно, в этом сеансе поддержка 5222 не подтверждена.

```sh
tcpdump -nni any 'tcp dst port 5222'
```

В SSH можно отдельно проверить, получается ли получить карту через
настроенные Cloudflare-маршруты.

```sh
/opt/sbin/d2ktg --check-telegram-dc-map /opt/d2k/config
```

Успешный вывод выглядит как
`{"ok":true,"stage":"help.getConfig","this_dc":2,"endpoint_count":42}`.
Числа здесь для примера. При сбое смотрите `ok:false`, например
`"error":"discovery_failed"`. Эта команда не записывает карту на диск.
Для диагностики фонового обновления посмотрите последние строки журнала.

```sh
tail -n 50 /opt/d2k/log/telegram.log
```

### HTTP-ошибки Worker D2O

Панель D2O может показать общую причину отказа маршрута. Если в диагностике
Worker виден конкретный HTTP-код и текст ответа, сверяйтесь с таблицей.

| Ответ Worker | Что проверить |
| --- | --- |
| **400** · `Expected the D2O 5222 WebSocket protocol` | Запрос на 5222 не содержит ожидаемый подпротокол. Проверьте, что на роутере версия D2O с поддержкой TCP 5222. Добавьте в панель только hostname и повторите проверку из Telegram. |
| **403** · `Telegram destination is outside the allowlist` | Worker не распознал адрес или IP отсутствует в допустимом списке. Для 5222 повторно извлеките адреса из текущей подтверждённой карты, проверьте формат и примените переменную. Для 443 сверяйте отдельно `D2O_TG_443_TARGETS`. |
| **501** · `Telegram 5222 is disabled` | Worker не нашёл ни одного корректного IP в `D2O_TG_5222_TARGETS`. Проверьте имя, тип Text, значение и факт Deploy. Если карта не содержит 5222, оставьте этот порт выключенным. |
| **502** · `Telegram 5222 connection failed` или `Telegram 443 connection failed` | Worker не смог установить маршрут к цели. Сверьте IP и порт в карте, повторите попытку и проверьте журнал. Если ошибка повторяется, приложите время, номер DC и код ошибки к обращению в поддержку. |

Если при открытии адреса Worker в обычной вкладке браузера отображается
**426** и `Expected WebSocket`, это ожидаемый ответ на HTTP-запрос без
WebSocket. Работу Telegram проверяйте из приложения через D2O.

## Частые вопросы

- **Команда не вывела IP.** Проверьте через `ls -l`, что файл существует и
  читается. Если в подтверждённой карте нет записей с портом 5222, оставьте
  `D2O_TG_5222_TARGETS` пустой. Telegram на 443 можно проверить отдельно.
- **Файла нет.** Проверьте, включён ли туннель Telegram и был ли успешный
  фоновый запрос карты. При нестандартных настройках путь может задаваться
  через `TG_DC_MAP_PATH`. Проверьте его на роутере командой
  `grep '^TG_DC_MAP_PATH=' /opt/d2k/config`. Используйте фактический путь
  и дождитесь подтверждённого обновления. Не создавайте карту вручную.
- **Cloudflare не принимает IP или Worker отвечает 403.** В поле Value
  должна быть одна строка IPv4/IPv6 через запятую. Проверьте, что скопированы
  реальные адреса из вывода, без префиксов, скобок и портов.
- **SSH не подключается.** При `ssh is not recognized` установите
  **OpenSSH Client** через дополнительные компоненты Windows, откройте
  терминал заново и повторите команду. При `Connection refused` проверьте,
  включён ли SSH и верен ли порт. При таймауте проверьте локальную сеть
  и адрес роутера. При `Permission denied` проверьте пользователя и пароль
  или ключ. Если на Keenetic открывается CLI KeeneticOS, сверяйте порт входа
  в Entware. При сообщении о смене ключа SSH сперва подтвердите новый отпечаток
  у администратора роутера.
- **Карта DC изменилась.** D2O обновляет карту на роутере, а список
  `D2O_TG_5222_TARGETS` хранится в Cloudflare. После изменения набора IP
  для 5222 снова откройте **Мои Workers** и скопируйте актуальную строку
  или получите её командой SSH. Замените значение и нажмите **Deploy**.
  Код Worker менять для обновления списка не требуется.
- **Нужно ли заменять рабочий Flowseal.** Если ваши подключения работают
  через 443, оставьте его. Добавьте Worker D2O, когда возникает потребность
  в исходящем TCP 5222 и панель сообщает, что Worker его не подтвердил.

## Проверка скачанного архива

Подпись Ed25519 над `latest.json` покрывает SHA-256
`d2k-telegram-worker.tar.gz` в поле `telegram_worker.sha256`. Используйте
публичный ключ из [репозитория D2O](https://github.com/t0fox/d2o/blob/main/docs/d2o-release-public.pem).

```sh
openssl pkeyutl -verify -pubin -inkey d2o-release-public.pem -rawin \
  -in latest.json -sigfile latest.json.sig
sha256sum d2k-telegram-worker.tar.gz
```

Сверьте выведенный SHA-256 с `telegram_worker.sha256` в проверенном манифесте.
